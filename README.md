# Vortaly

Узбекский конструктор приложений для малого бизнеса: владелец описывает свой
бизнес словами, ИИ собирает сайт и Telegram Mini App с услугами, ценами и
онлайн-записью на русском и узбекском. Первый пилот — запись в салон красоты
или барбершоп. Планируемый корневой домен задаётся через
`NEXT_PUBLIC_ROOT_DOMAIN` (по умолчанию `vortaly.com`; домен пока не подключён).
Демо-салон — «Chinor».

Next.js 16 (App Router) · React 19 · Tailwind CSS 4 · TypeScript

## Название

Продукт называется **Vortaly**. В интерфейсе, документации и любых
пользовательских текстах используются только эти формы:

- **Vortaly** — продукт в целом;
- **Vortaly AI platform** — платформа, на которой работают проекты (в тексте
  обычно достаточно короткого Vortaly);
- **Vortaly Mini App** — приложение, которое открывает клиент бизнеса;
- **Vortaly Console** — консоль оператора платформы (корневой домен, `/`).

Название проходит через весь проект: env-переменные `VORTALY_*`, компоненты
(`VortalyAdminShell`), ключи `localStorage` (`vortaly.*`), cookie сессии
(`vortaly.admin`), служебная папка `.vortaly/`, заголовок `x-vortaly-tenant`,
имя пакета `vortaly-beauty`.

Корневой домен задаётся через `NEXT_PUBLIC_ROOT_DOMAIN`; значение по умолчанию —
`vortaly.com`. Домен ещё не куплен и не настроен, поэтому это заполнитель, а не
окончательный адрес: перед запуском его нужно подтвердить и обновить в
окружении деплоя.

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000
```

Остальные команды: `npm run build`, `npm start`, `npm run typecheck`,
`npm run lint`, `npm test`.

Локальный запуск без доступа к боевому Supabase: `node .claude/dev-local.mjs`
(порт 3100). Лаунчер обнуляет ключи Supabase, Telegram и оплаты, подставляет
тестовый секрет администратора `vortaly-local-dev` и фиктивный токен бота;
черновики и данные пишутся в `.vortaly/`.

Деплой на Vercel без своего домена — пошагово в `docs/deploy-vercel.md`.

## Ключи

Создайте локальный `.env.local` на основе `.env.example` и заполните нужные
значения. Next.js читает `.env.local`; никогда не добавляйте его в Git.

Полный список переменных — в `.env.example`. Без ключей приложение работает на
демо-данных: запись создаётся, но не сохраняется на сервере.

## Две поверхности

Корневой домен — Vortaly Console.

Слева — проекты из `GET /api/admin/salons`. Пока список пуст (например, без
Supabase) показываются демо-проекты с явной пометкой об этом, чтобы их не
приняли за реальных арендаторов. Есть кнопка обновления, и после создания
бизнеса список перезапрашивается, а новая строка подсвечивается.

В центре — форма создания бизнеса: название и телефон `+998`, плюс вид бизнеса,
который подставляет `tagline_ru` / `tagline_uz`. Поддомен считается прямо при
вводе той же функцией `slugify`, что и на сервере, поэтому превью не может
разойтись с тем, что вернёт API. Отправка — `POST /api/admin/salons`.

Справа — терминал. Он показывает **реальный процесс**, а не анимацию:
`POST /api/admin/provision` стримит NDJSON, по одному событию на фактически
выполненный шаг — приём данных, вывод слага, проверка занятости, список таблиц
арендатора, вставка в `salons`, чтение записи обратно, резерв поддомена,
разрешение хоста через `proxy.ts`, экраны и локали, итог. Каждая строка
сообщает о том, что действительно было сделано; то, что ещё не автоматизировано
(DNS-запись и TLS-сертификат), помечается как `warn`, а не выдаётся за готовое.

Клиент читает поток по мере поступления и показывает строки с паузой ~150 мс,
чтобы их можно было прочитать; терминал не закрывается, пока поток открыт. При
`prefers-reduced-motion` лог показывается сразу целиком.

`POST /api/admin/salons` при этом не изменён и продолжает создавать арендатора
одним вызовом — провиженинг-роут выполняет ту же операцию через тот же слой
данных (`lib/supabase/salons.ts`), только с отчётом по шагам.

Созданный проект сразу появляется карточкой наверху левой панели. Если запись
зафиксирована — статус «Работает» и рабочая ссылка на Vortaly Mini App. Если нет —
статус «Ошибка», причина из ответа сервера и **никакой ссылки**: без базы
арендатора не существует, и ведущая в 404 ссылка была бы хуже её отсутствия.

`<slug>.<NEXT_PUBLIC_ROOT_DOMAIN>` — Vortaly Mini App арендатора. В продакшене
арендатор определяется по Host в `proxy.ts`; локально те же экраны открываются по пути
(`/chinor`, `/coffee`), и консоль ссылается именно туда. Готов пока только
`chinor`, остальные показывают экран сборки.

## Как устроена запись

Вся запись — на одной странице, пятью раскрывающимися блоками: услуга (с
фильтром по категориям), мастер, дата и время, контакты, способ оплаты. Блок
открывается только когда заполнены предыдущие; заполненный сворачивается в
строку с ответом, по тапу открывается снова. Внизу — закреплённая строка с
суммой и единственным действием.

Состояние разделено надвое: незавершённый черновик живёт в
`lib/booking/store.tsx` (`localStorage`, ключ `vortaly.draft`), подтверждённые
записи — в `lib/data/bookings.ts` (ключ `vortaly:admin:bookings`). Сетка времени
читает второй источник, поэтому список записей и занятость слотов не могут
разойтись: только что созданная бронь сразу закрывает своё время.

Язык живёт в одном месте — `LocaleProvider` из `lib/i18n/context.tsx`.
`I18nProvider` берёт язык оттуда и добавляет `t()` для строк из словарей и
`tr()` для полей вида `{ ru, uz }`. При первом заходе язык берётся из
`language_code` Telegram, дальше — из явного выбора.

## Дизайн

Визуальная тема — узбекская майолика: фарфоровый фон, цвет окисленной меди для
текста, самаркандская бирюза как основной акцент, гранат и шафран. Сетка
времени сделана как стена глазурованной плитки: свободный слот ловит блик,
занятый — матовый бисквит с перечёркиванием, выбранный — гранатовая глазурь.

Шрифты: Unbounded (заголовки) и Manrope (интерфейс), оба с кириллицей.
Светлая и тёмная тема через `prefers-color-scheme`.

## Что сделано заглушкой

### Supabase

`lib/supabase/bookings.ts` работает, но деградирует мягко: без ключей запись
возвращается обратно клиенту и хранится в `localStorage`. Чтобы включить
Postgres — примените `supabase/schema.sql` и заполните `.env.local`. Формы
данных совпадают, UI менять не нужно.

Каталог (салоны, услуги, мастера) пока читается из `lib/data/salon.ts`.
Следующий шаг — заменить эти функции на запросы к Supabase.

### Оплата

`/api/payments/click` и `/api/payments/payme` собирают **настоящие ссылки на
хостед-чекаут** (формат URL и base64-параметры Payme корректны), но денег не
принимают. Чтобы включить приём платежей, нужно:

1. **Click** — реализовать Prepare и Complete, которые Click вызывает
   server-to-server, и проверять md5-подпись (`lib/payments/click.ts`).
2. **Payme** — реализовать JSON-RPC методы `CheckPerformTransaction`,
   `CreateTransaction`, `PerformTransaction`, `CancelTransaction`,
   `CheckTransaction` и проверять Basic-авторизацию.
3. Переводить запись в статус `paid` **только** из серверного колбэка —
   никогда по `return_url`, его можно подделать в браузере.

### Telegram

SDK подключён, есть haptics и данные пользователя. Подпись `initData`
проверяется на сервере (`lib/telegram/init-data.ts`), поэтому
`telegramUserId` берётся только из проверенных данных. О новой и отменённой
клиентом записи бот пишет всем владельцам бизнеса (`lib/telegram/notify.ts`);
Telegram доставит сообщение только тому, кто хотя бы раз нажал Start у бота.

## Конструктор сайтов и ИИ

`/builder/<slug>` — ИИ-редактор и ручной редактор слева, настоящая страница
бизнеса справа. ИИ правит только черновик; клиенты видят изменения после
«Опубликовать». Модель предлагает изменения из закрытого списка операций
(`lib/builder/spec.ts`), их применяет сервер.

Оплата ИИ — гибрид (`lib/ai/access.ts`): у каждого сайта
`VORTALY_FREE_AI_ACTIONS` (по умолчанию 5) бесплатных действий на ключах
платформы, дальше владелец вставляет свой бесплатный ключ Gemini, Groq или
OpenRouter. Ключ проверяется у провайдера, хранится зашифрованным
(AES-256-GCM, `VORTALY_KEY_SECRET`) и в браузер не возвращается.

## Вход для владельцев

Владелец входит через Telegram на `/owner` (виджет Telegram на сайте или
`initData` внутри Telegram). К бизнесу аккаунт привязывается только по
одноразовой ссылке, которую оператор создаёт в конструкторе кнопкой
«Пригласить владельца» (7 дней). Владелец видит и правит только свои бизнесы;
оператор платформы — все, по `PLATFORM_ADMIN_SECRET`.

## Запуск внутри Telegram

1. `@BotFather` → `/newapp`, указать URL приложения (для локальной разработки
   подойдёт туннель, например `ngrok http 3000`).
2. CSP в `next.config.ts` уже разрешает фрейм с `web.telegram.org`.
